# Minta — NutriScan

## Краткое ТЗ

**Цель.** Создать кроссплатформенное мобильное приложение со сканером штрихкодов и REST API. Пользователь получает понятную оценку продукта, расшифровку состава, предупреждения об аллергенах и пищевых ограничениях, а также сравнение цен в ближайших магазинах.

**Проблема.** Покупателю сложно быстро понять химические названия ингредиентов и скрытые источники аллергенов. Ошибка особенно критична для людей с аллергиями и тех, кто придерживается специальных диет.

**Решение.** NutriScan объясняет состав простым языком, проверяет ограничения пользователя и показывает альтернативные товары и цены в сетях Самокат, ВкусВилл, Магнит и Пятёрочка.

### Роли

| Роль | Возможности |
|---|---|
| Покупатель | Сканировать товар, смотреть состав и оценку, задавать ограничения, сравнивать альтернативы и цены |
| Администратор каталога | Добавлять и обновлять карточки товаров, составы и данные об аллергенах |
| Поставщик данных | Передавать каталог товаров и актуальные предложения магазинов |

### Основные сущности

| Сущность | Ключевые данные |
|---|---|
| Пользователь | ID, имя, пищевые ограничения |
| Продукт | ID, штрихкод, название, бренд, оценка |
| Ингредиент | Название, описание, категория |
| Аллерген | Название, синонимы |
| Ограничение | Тип диеты или аллергии пользователя |
| Магазин | Название, координаты |
| Предложение | Продукт, магазин, цена, наличие |

### Пользовательские сценарии

1. Покупатель сканирует штрихкод и получает карточку продукта.
2. Покупатель читает расшифровку состава и понятную оценку полезности.
3. Приложение предупреждает о найденном аллергене или несовместимости с ограничением пользователя.
4. Покупатель сравнивает цену этого продукта в ближайших магазинах.
5. Покупатель находит более дешёвый или подходящий по составу аналог.

### HTTP API текущего каркаса

| Метод | Путь | Назначение | Ответ |
|---|---|---|---|
| `GET` | `/projects` | Получить демонстрационный список проектов Minta | `200 application/json` |

`POST /projects` и остальные несуществующие маршруты не поддерживаются. Для `GET /projects` сейчас используются мок-данные прямо в handler; пакеты `internal/usecase` и `internal/storage` подготовлены для следующих этапов.

## Запуск локально

Требуется Go 1.22 или новее.

```powershell
go run ./cmd/api
```

Сервер слушает `:8080`. Проверить ответ можно из PowerShell:

```powershell
Invoke-RestMethod http://localhost:8080/projects
```

Тесты:

```powershell
go test ./...
```

## Docker

Сборка и запуск:

```powershell
docker build -t minta-api .
docker run --rm -p 8080:8080 --name minta-api minta-api
```

В другом окне PowerShell:

```powershell
Invoke-RestMethod http://localhost:8080/projects
```

Из PowerShell переменную окружения задайте так:

```powershell
$env:HTTP_ADDR = ':8081'
go run ./cmd/api
```

Для сравнения ответа контейнера с ответом на хосте запустите API в Docker, затем выполните:

```powershell
$hostResponse = curl.exe -s http://localhost:8080/projects
$containerResponse = docker run --rm --network container:minta-api curlimages/curl:latest -s http://localhost:8080/projects
$hostResponse -eq $containerResponse
```

Последняя команда должна вывести `True`.
